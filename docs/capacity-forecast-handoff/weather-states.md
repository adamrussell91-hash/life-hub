# Weather states and supplied icon contract

Adam will provide these final icons, numbered 1–30. The designed set includes transparent 512px PNGs and scalable SVGs. Do not substitute an automatically generated asset set for his supplied files.

These states describe the capacity pattern and its causes, not thirty score brackets. A score communicates amount; the icon communicates conditions. Each state needs a brief evidence-based explanation. Same score can have different weather. Avoid an illness/distress interpretation without supporting evidence.

## Rendering rules

Select a state using current domain pattern, expected trend and available evidence; update it when check-ins change that state. Use a coherent colour family along the forecast line: sunny/readiness, cloud/fatigue, fog/cognition, gusts/fragmentation, rain/emotional strain, storms/overload, and clearing/recovery. Preserve icon shape and text alternatives so colour is never the sole signal.

Show only meaningful predicted changes, supported by observations or clearly labelled assumptions. Use fewer icons than forecast sample points. Tapping a point shows contributors and uncertainty. The shaded band represents prediction uncertainty; do not describe the prototype band as calibrated.

Under the headline score, explain why: “Recent energy is improving, but yesterday’s heavy workload may still limit recovery. Last night’s sleep is unconfirmed.” With new answers, update that explanation. Generic “Bright spells” alone was explicitly rejected.

A Corey event explanation could say “Your previous check-ins suggest an emotional lift around time together; physical fatigue may remain.” Scheduled lunch/tea may indicate a possible lift, never confirm intake or automatic recovery.
