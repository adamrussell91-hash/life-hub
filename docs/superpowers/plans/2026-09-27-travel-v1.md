# Travel v1: the trip planner (build brief for Cursor)

**Why this exists.** Adam is travelling for six weeks: Sydney, Kuala Lumpur, Istanbul, Scotland, London, Rome, then Seoul. He leaves on **Tue 1 Dec 2026**. He needs one place that plans the trip, gets him through each day without getting lost, and lets people follow along. He has approved a clickable mockup. This brief turns that mockup into a real app on the umbrella site.

**Hard deadline.** It must be usable on his iPhone by **Sun 15 Nov 2026**. That leaves two weeks of real use before he flies.

Branch: `travel/v1`, from fresh `main`. One draft PR for the whole build. Adam merges it himself.

**Where the private material lives.** This repo is public. Adam's trip, the approved mockup and his design notes are in the **private** repo `adamrussell91-hash/life-hub-data`. Clone it next to this one (`~/Projects/life-hub-data`) before you start. You need:

- `data/travel/design/DESIGN-DIRECTION.md`: Adam's design rules and his reasons.
- `data/travel/trips/trp_mpzfqqa5g57m.json`: Adam's real trip, already in the §3 shape. **The app reads and writes this file.**

**If this brief and the mockup disagree, this brief wins. ### 2.3 Storage: the private `life-hub-data` repo
All trip data lives in `adamrussell91-hash/life-hub-data`, the same private repo the rest of Life Hub uses. **No new Netlify Blobs store.** The Life site already has `GITHUB_REPOSITORY`, `GITHUB_BRANCH` and `GITHUB_TOKEN` set for this repo, so no new secrets are needed.

| Path in `life-hub-data` | Contents |
|------|----------|

| `data/travel/share-tokens.json` | `{ "<sha256 hex of token>": { "trip_id": "...", "created_at": "..." } }` |

- Write `netlify/functions/_shared/travel-repository.mjs` on top of `createGitHubClient`:
  - `listTrips()`: `resolveTree()` and pick the paths under `data/travel/trips/`
  - `getTrip(id)`: returns `{ trip, version }`, where `version` is the file's blob sha
  - `createTrip(trip)`
  - `saveTrip(trip, version, message)`
  - `deleteTrip(id, version)`
  - `getShareTokens()` and `saveShareTokens(map, version)`
- **One file per trip, and every save is one commit.** Commit messages read like a log line: `travel: add "Sky Garden" to 13 Dec`, `travel: check-in KL`, `travel: edit "<item title>"`. They may name items, because that repo is private.
- **Stale edits:** every write sends the `version` (sha) it read. A GitHub `409` or `422` "sha does not match" becomes our `409 conflict`. The client then re-fetches the trip, re-applies the same edit once, and retries. If that fails too, it shows "This trip changed somewhere else. Reload to see the latest." Adam edits alone, so this is enough; don't build per-item files.
- **Reads:** the trip GET goes through the tree/blob API the same way `github-professional-data.mjs` reads `people.json`. Keep a 30-second in-memory cache per function instance, keyed by sha, and drop it on every write.
- **Exchange rates** are cached in memory per function instance for the calendar day. They are never written to the repo.
- **Local dev and tests** never touch GitHub. The Vite mock API serves `apps/travel/fixtures/test-trip.json`. Function tests inject a fake GitHub client, as the existing professional tests do.

### 2.7 Money: one currency on screen
- Show every cost in **AUD**.
  - Costs entered in AUD show exact cents: `A$154.26`.
  - Costs in other currencies show `≈ A$455`, rounded to whole dollars, using the rate saved when the item was saved.
- Store `{ amount, currency, aud, rate, rate_date }` when an item is saved. **Never recompute old items with today's rate.**
- The local currency appears in only two places: the arrival guide's money row, which is authored text like "RM10 is about A$3.50", and the add form's "Shows in the plan as ≈ A$…" hint.

### 2.8 Time: always the city's local wall-clock time
- Every item stores `date` (`YYYY-MM-DD`) and `time` (`HH:MM`) in the **city's local time**. The city stores an IANA zone.
- Two helpers go in `apps/travel/src/lib/time.ts`, with the tests listed below:
  - `zonedToInstant(date, time, tz): Date`. Use the standard Intl offset loop: guess UTC, read the offset with `Intl.DateTimeFormat(..., { timeZone: tz, timeZoneName: 'longOffset' })`, correct, and repeat once.
  - `formatInZone(instant, tz, opts)`.
- Required tests:
  - `2026-12-04 08:30 Europe/Istanbul` → Sydney shows `16:30` the same day
  - `2026-12-09 20:00 Europe/London` → Sydney shows `07:00` on `10 Dec`, labelled "(next day)"
  - `2026-12-02 18:00 Asia/Kuala_Lumpur` → Sydney shows `21:00`
- "Now there" clocks use `formatInZone(new Date(), city.tz)`. Never compute them from `getTimezoneOffset()`, which is what the mockup did.

## 3. Data model (copy into `apps/travel/src/types.ts` and mirror in `netlify/functions/_shared/travel-schema.mjs`)

```ts
export type IsoDate = string;   // 'YYYY-MM-DD'
export type HHMM = string;      // '09:35'
export type Currency = 'AUD' | 'MYR' | 'TRY' | 'GBP' | 'EUR' | 'KRW' | 'CAD' | 'USD' | 'JPY' | 'NZD' | 'SGD';
export type SceneId = 'kul' | 'ist' | 'sco' | 'lon' | 'rom' | 'sel' | 'generic';
export type Status = 'planned' | 'booked' | 'todo' | 'idea';   // 'planned' shows no tag
export type HopMode = 'walk' | 'train' | 'tram' | 'bus' | 'taxi' | 'ferry';
export type GuideIcon = 'phone' | 'transport' | 'money' | 'weather' | 'paperwork';

export interface Money { amount: number; currency: Currency; aud: number; rate: number; rate_date: IsoDate }
export interface Place { name: string; lat: number; lon: number; address?: string }
export interface Hop { mode: HopMode; minutes: number; note?: string; cost?: Money }

export interface City {
  id: string;                 // slug, unique in trip: 'kul', 'ist', 'sco', …
  name: string;               // 'Kuala Lumpur'
  country: string;
  tz: string;                 // IANA, 'Asia/Kuala_Lumpur'
  start_date: IsoDate; end_date: IsoDate;   // inclusive; cities never overlap except on travel days (see below)
  title: string;              // 'Kuala-ering' — shown big on the scene
  scene: SceneId;
  accent: { color: string; soft: string; ink: string };   // the only hex allowed outside tokens
  facts: string[];            // chips on the scene, e.g. '31°, feels like 40°'
  center: { lat: number; lon: number };                   // map fallback centre
  local_currency: Currency;
  driver_phrase?: { local: string; english: string };
  arrival_guide?: { title: string; rows: { icon: GuideIcon; text: string }[] };   // text may contain <b>…</b> only
  directions_app: 'google' | 'naver';                     // 'naver' for South Korea
}

interface ItemBase {
  id: string;                 // 'itm_' + 12 random base32 chars
  city_id: string;
  date: IsoDate;              // local date in that city
  time: HHMM | null;          // null = "Time to set"
  title: string;
  note: string;               // plain text
  status: Status;
  cost?: Money;
  booking_ref?: string;       // PRIVATE — never leaves the owner API
  private?: boolean;          // PRIVATE items never leave the owner API (e.g. medication)
  link?: string;              // https only
  hop?: Hop;                  // how you get from THIS item to the NEXT one
  created_at: string; updated_at: string;
}
export interface PlaceItem extends ItemBase { kind: 'do' | 'food' | 'transit' | 'med'; place?: Place; off_map_label?: string }
export interface StayItem extends ItemBase {
  kind: 'stay'; place?: Place; nights: number; check_out_date: IsoDate; check_in_time?: HHMM;
  cancel_until?: string; home_base: boolean;            // home_base powers "Take me home" for every night in [date, check_out_date)
}
export interface TicketItem extends ItemBase {
  kind: 'flight' | 'train'; carrier: string; number: string;
  from_code: string; to_code: string; from_name?: string; to_name?: string;
  depart_time: HHMM; arrive_time: HHMM; arrive_date: IsoDate; arrive_city_id?: string;
  source?: string;            // 'Trip.com', 'Expedia' …
}
export interface CheckinSlot extends ItemBase { kind: 'checkin_slot' }   // planned check-in, e.g. 'Breakfast check-in'
export type Item = PlaceItem | StayItem | TicketItem | CheckinSlot;

export interface Checkin { id: string; at: string /* ISO instant */; city_id: string; label: string }

export interface DayMeta { city_id: string; date: IsoDate; subtitle?: string; penelope_prompt?: string }

export interface Trip {
  id: string; schema_version: 1;
  title: string;              // 'Sydney to Seoul, the long way'
  start_date: IsoDate; end_date: IsoDate;
  home_tz: 'Australia/Sydney' | string;
  followers_label: string;    // who follows the public link, e.g. two first names — shown on check-in rows
  cities: City[];             // ordered by start_date
  items: Item[];
  days: DayMeta[];            // optional per-day subtitle + Penelope question
  checkins: Checkin[];
  share: { enabled: boolean; created_at: string | null };   // token hash lives under share/<hash>, not here
  created_at: string; updated_at: string;
}
```

**Rules that follow from the model (each one gets a unit test):**
1. **Day list for a city** = every date from `start_date` to `end_date`, plus any other date that has an item for that city. Sort ascending. A travel day, such as 4 Dec (leave KL, arrive Istanbul), appears in **both** cities. Items belong to the city given by their `city_id`.
2. **Item order in a day** is `time` ascending. Items with `time: null` go **first**, labelled "Time to set". Ties keep insertion order. Tickets sort by `depart_time`. Checking this is D2.
3. **Numbered pins:** in the day's order, give numbers 1, 2, 3… only to items that have a `place` and aren't stays. Stays show the bed icon. Tickets show a plane or train icon and no number. The numbers in the list and on the map come from the **same function**: `numberStops(items)` in `src/model/day.ts` (V4).
4. **Home base on a night N** is the `StayItem` with `home_base: true` and `date ≤ N < check_out_date`. If there are several, use the latest `updated_at`. "Take me home" uses the home base for the **selected day's** date.
5. **The arrival guide** shows on the first day of a city, and on any day with a `TicketItem` whose `arrive_city_id` is that city.
6. **Hop fallback:** if an item has no `hop` and both it and the next pinned item have places less than 2.5 km apart, show `≈ N min walk`. N = round(haversine_km × 1.3 / 0.08), because 80 m/min is walking pace. Otherwise show nothing.
7. **Still to book** is built by one model function, `buildTodo(trip, today)`, that returns rows `{ when_label, title, detail, city_id, date }` in this order:
   - (a) every item with `status: 'todo'`, by date
   - (b) every night between the trip's start and end with **no** stay covering it, merged into ranges like "10–13 Dec · No bed", except the last night of the trip
   - (c) every stay with `cancel_until` in the future, labelled "Free cancellation ends …"

   The chip's count and the list both come from this one function (V4).

## 4. API (all under `/api/`, all use the `{ ok, data | error }` envelope from `http.mjs`)

| Method + path | Auth | Body / query | Returns |
|---------------|------|--------------|---------|
| `GET /api/travel-trips` | operator | — | `{ trips: TripSummary[] }` (id, title, start_date, end_date, city names) |
| `POST /api/travel-trips` | operator | `{ title, start_date, end_date }` **or** `{ import: TripImport }` | `Trip` (201) |
| `GET /api/travel-trip?id=` | operator | — | `{ trip: Trip, version }` (every write returns the same shape) |
| `PATCH /api/travel-trip?id=` | operator | `{ if_version, patch: Partial<Trip minus items/checkins> }` | `Trip` · `409 conflict` if stale |
| `DELETE /api/travel-trip?id=` | operator | — | `{ id, deleted: true }` |
| `POST /api/travel-items?trip=` | operator | `{ if_version, item: ItemDraft }` | `Trip` |
| `PATCH /api/travel-items?trip=&id=` | operator | `{ if_version, item: ItemDraft }` | `Trip` |
| `DELETE /api/travel-items?trip=&id=` | operator | `{ if_version }` | `Trip` |
| `POST /api/travel-checkins?trip=` | operator | `{ city_id, label }` | `Trip` (server sets `at` to now) |
| `POST /api/travel-share?trip=` | operator | — | `{ url }`: `https://life-hub.adam-russell.com/travel/t/<token>` (the token is 32 random bytes as base64url; store only its sha256, in `share-tokens.json`) |
| `DELETE /api/travel-share?trip=` | operator | — | `{ enabled: false }` and deletes the `share/<hash>` key |
| `GET /api/travel-public?token=` | **none** | — | `PublicTrip` (redacted, see below) or 404 |
| `GET /api/travel-places?q=&lat=&lon=` | operator | — | `{ places: Place[] }` (max 6) |
| `GET /api/travel-rates?from=` | operator | — | `{ from, to:'AUD', rate, date }` |
| `POST /api/travel-parse` | operator | `{ text }` (max 20,000 chars) | `{ draft: ItemDraft, confidence: 'high'\|'low', missing: string[] }`. **It never saves.** |

**The server converts money.** When an `ItemDraft` has `cost: { amount, currency }` without `aud`, the server fetches the day's rate (cached) and fills in `aud`, `rate` and `rate_date`. The client never sends its own rate.

**Redaction (`redactTrip(trip) → PublicTrip`, a pure function in `_shared/travel-redact.mjs`, with a test per rule):**
- Drop every item with `private: true` or `kind: 'med'`.
- Drop `booking_ref`, `cost`, `link`, `source` and `note` from every item. The note can hold private things, so the public view shows titles, times and places only.
