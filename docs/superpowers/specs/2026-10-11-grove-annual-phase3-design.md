# Grove annual world Phase 3 design

Authorised by Adam: implement Phase 3. Base: Phase 2 commit 67a104c8. Build weekly ownership and task planting on verified annual geography, with a diagnostic activity consumer. Chunked production rendering, animated water/wildlife and final Home/calendar rollout remain subsequent phases from the parent specification.

## Weekly geography

Generate Monday–Sunday intervals intersecting the year, clipping each portion to year boundaries. The region ID includes the annual year and original Monday, so New Year portions have distinct ownership. Support 53 and 54 intervals and leap days. Terms annotate activity plans, never influence region seeds or boundaries.

Use the annual final bed and explicit water triangles. Build a cardinal dry-land graph with continuous water-crossing checks and a comfortable slope limit. Retain the largest connected component; unsuitable isolated islands remain quiet landscape. Select geographically spread anchors along a deterministic connected traversal, then partition by terrain-weighted multi-source graph distance. Every owned cell must reach its anchor through its region. Rivers and steep ridges constrain paths. Normal rendering never paints region borders.

Precompute candidate grid sites with deterministic small coordinate jitter, mature trunk spacing >=2.6m, slope <=0.5, wet exclusion and >=2m water clearance. Protected sparse meadow corridors contain no candidates. Each week has stable primary and ordered overflow sites; minimum capacity 200, evaluated independently of tasks. If allocation cannot establish capacity, fail explicitly rather than assign submerged or colliding fallback positions. Geometry and ownership are year/version-only derived data; transfer the ownership buffer and validate calendar, shapes, connected ownership, sites and capacity before consumption.

## Activity and stability

Reuse groveCompletions, Sydney date handling, species and late overrides, growthAt/stageFor/scaleFor, wildlife eligibility and saved/provisional calendars. Exactly one tree for every live dated completed task at/before the reference time in loaded annual worlds. Deduplicate IDs deterministically. Deletion/reopening removes a tree; domain edits preserve its position. Date edits move it only when its weekly ownership changes. Filtering Day/Week/Term/Year never reallocates trees: build annual placements first, then select visible history.

Each task gets a seeded candidate sequence. Deterministic ID ordering resolves conflicts on cold reconstruction; ecological suitability ranks sites (Life higher, Teaching gentle, Health shore-adjacent dry, Wedding open, Other/Late remaining suitable land). These preferences cannot omit valid tasks. Exhaust primary sites before ordered same-week overflow. A spatially reserved slot is unique, and all candidates meet mature spacing before any task arrives. Capacity exhaustion throws a visible error with the affected week and counts; never stack, omit or plant unchecked fallback trees.

Strict spacing plus fully invariant positions under arbitrary insertion/deletion cannot be guaranteed by a finite stateless conflict allocator. Chosen explicit tradeoff: a session allocator preserves surviving task-to-slot assignments, then allocates new records deterministically. It has no browser storage/backend writes; reconstructing after reload is deterministic for the same record set but may move collision-chain survivors after historical edits. Movement tolerance during a session is zero for surviving tasks in unchanged weekly ownership, including backdated insertion, deletion and domain edits. Growth/model changes do not change positions. Session data is a disposable derived cache, not earned game state.

Baseline scenery remains activity-independent. Activity flowers/grass use bounded dry candidate sites and preserve corridors. Future dates receive no invented completed trees or unearned wildlife. Annotate days/regions from actual terms and retain provisional status.
