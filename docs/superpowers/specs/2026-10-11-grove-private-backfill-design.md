# Private Grove history backfill

Adam authorized loading the completed 2026 weekly table, including modelled daily/late/book data, and explicitly requested no estimate labels. This is decorative private Grove history; do not create hundreds of task-board records or publish personal counts in Git.

Expose a validated optional `grove_history` field through the existing operator-protected private hub preferences API, backed by its own `meta/grove_history` blob so unrelated whole-preference writes cannot erase it. A small Grove import control accepts a local JSON file, validates and saves only that field while preserving all other preferences. Render the saved history alongside live task history. Missing/invalid history keeps existing behavior. History is replaceable and deterministic, not additive on repeated import. The product UI uses normal completed-work language, without provenance/estimate badges.

Payload v1 contains years with full weekly ranges and per-area counts, optional per-Grove term dates, optional book completion dates, and a late fraction. Source data is private and supplied only through the local import file. Future unchecked weeks are omitted; zero checked weeks stay explicit. Counts are finite nonnegative integers, total and payload sizes bounded, dates real and ordered, ranges nonoverlapping, books valid dates, fraction 0..1. Reject invalid import rather than partly saving it.

Pure deterministic adapter produces completed Grove-only inputs from weekly counts. Teaching/Gifted/HALT map teaching; University/Career/Professional/Unclassified map other; Life/Health/Wedding retain domains. Spread completions across available Sydney days, favour weekdays in term and flatter in breaks, with stable IDs per week/domain/index. Internally identify these as historical entries. Use supplied configured late fraction deterministically with prior-day due dates for selected entries. No UI labels are required. The invented dates must never become ordinary task records.

Live completed task counts in covered week/domain consume the supplied weekly baseline before generating remaining history entries, preventing double counting. Preserve live records and allow totals above baseline if real live history exceeds it. Reopened/deleted live task records remain excluded via existing canonical liveness handling. Future weeks and dates after now never plant trees. Grove-only terms override the year for rendering/milestones, without changing global school preferences. History books merge by stable date IDs with live books. Synthetic historical tree cards omit the broken Open task link.
