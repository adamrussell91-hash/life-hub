## Failures (proven)

### F1 — Tasks / Dashboard (`#/board`, the hub's home) / entire page
- **Must:** The Tasks Hub home page (brand-click destination, mobile "Home" tab, default landing route) should render the board.
- **Must-not:** A hard crash on the hub's own front door.
- **Verify:** Load `https://life-hub.adam-russell.com/tasks/` (desktop 1280×800 and phone 390×844, fresh load and via `#/board`).
- **Evidence:** Renders only: "Could not load Dashboard: Cannot read properties of undefined (reading 'some')" with a "Retry" button. Retry does not fix it. Reproduced identically on both viewports. This blocks reaching the Board columns/cards described in spec §4.1 entirely from this route (Board content was viewed indirectly via other views instead).

### F2 — Teaching / Trash / Restore button
- **Must:** Restore should show a confirm card before executing (spec: "Restore / destroy ask a confirm card, not `window.confirm`").
- **Must-not:** Instant execution with no confirmation.
- **Verify:** Teaching → Trash → click "Restore" on any row.
- **Evidence:** Clicked "Restore" on "Memory, Identity and Ono" (trashed 27/08/2026) → banner "Restored 'Memory, Identity and Ono'." appeared immediately, item left Trash and became a **Published** lesson under "Artist of the Floating World" — no dialog at any point. By contrast, "Move to trash" on the same lesson (from Lessons → row menu) correctly opens a confirm card ("Move 'Memory, Identity and Ono' to trash? You can restore it later from Trash." / Cancel / Move to trash). So the confirm pattern exists in the codebase but was not applied to Restore. **I re-trashed the lesson afterward to undo the accidental restore.**

### F3 — Tasks / Graph, Blockers mode (`#/graph`)
- **Must:** Default Graph view (Blockers) should render nodes/edges or a labelled empty state.
- **Must-not:** A hard crash.
- **Verify:** Tasks → Graph (or `#/graph` directly).
- **Evidence:** "Could not load Graph: Cannot read properties of undefined (reading 'length')."

### F4 — Tasks / Graph, Universe mode (`#/universe`)
- **Must:** Universe mode should render the solar-system scene or a labelled empty state.
- **Must-not:** A hard crash.
- **Verify:** Tasks → Graph → Universe pill (or `#/universe` directly).
- **Evidence:** "Could not load Universe: t.tags is not iterable." Combined with F1 and F3 (both "reading 'some'"/"reading 'length'" on undefined), this looks like one shared root cause: some task/project record has a malformed `tags` field (not an array), and several views that iterate the shared task collection (Board, Blockers graph, Universe) all break on it. Orbit, Branch, and Sky modes — which presumably don't touch `tags` the same way — rendered fine.

### F5 — Teaching / Units / unit cover image (stale host)
- **Must:** Unit cover images should load from the current API host.
- **Must-not:** Reference the retired host (explicitly called out in STRESS-TEST.md's Locked facts as a FAIL).
- **Verify:** Teaching → Units → "Artist of the Floating World" card.
- **Evidence:** `<img>` src is `https://teaching-api.adam-russell.com/api/media/media_mt1hy3vq_eqrm4j/file` (naturalWidth 0 — failed to load). The correct host per spec is `api.adam-russell.com`.

### F6 — Teaching & cross-hub / CORS blocking `unit-templates` / `lesson-templates` / `repo/manifest`
- **Must:** These API calls should succeed against `api.adam-russell.com`.
- **Must-not:** Be blocked by CORS.
- **Verify:** Console errors while on Teaching → Templates and while on Life → Central Node.
- **Evidence:** `Access to fetch at 'https://api.adam-russell.com/api/unit-templates' ... blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present`, same for `/api/lesson-templates`, and `/api/repo/manifest?from=...&to=...` blocked with `Request header field if-none-match is not allowed by Access-Control-Allow-Headers in preflight response`. This is the direct root cause of F12 below (Templates page).
